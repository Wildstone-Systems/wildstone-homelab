# Friction log

Every surprise hit while dogfooding the migration
([migration.md](migration.md)) gets a row **when it happens**, not
from memory later. A row is closed by a fix (link the commit/PR) or an
explicit deferral with a reason — silent deferral is not a state.
Alpha exit requires this table empty or all-deferred-with-reasons
(ADR-W018 A4).

Severity: **blocker** (migration step cannot proceed) · **papercut**
(worked around, but wrong) · **polish** (confusing, cosmetic).

| F51 | 2026-09-04 | Secrets / recovery | blocker | `wild secret set lldap-admin-password` reports success and changes nothing. Verified: the recreated container's `LLDAP_LDAP_USER_PASS` matched the new value byte for byte and the directory still returned 401. Worse than inert: if the volume is ever lost the env value becomes authoritative again, so Wildstone's stored secret and the directory can diverge with no signal either way. The only recovery found was destroying `lldap-data`. | open |
| F52 | 2026-09-04 | Secrets / rotation | blocker | Rotating a secret does not propagate to files already materialized from it. A ConfigFile's content carries a REFERENCE, so rotating the value leaves the content — and therefore the config digest — unchanged, nothing rewrites the file, and every consumer keeps using the pre-rotation value indefinitely while the system reports healthy. Verified end to end: `wild secret set lldap-admin-password` took the secret to version 3, `/etc/wildstone/identity/configuration.yml` still held the version-1 value, and Authelia failed its service bind with `LDAP Result Code 49 "Invalid Credentials"` while `wild status` showed zero unhealthy resources. The only recovery found was deleting the materialized file so drift repair rewrote it. This is general, not LLDAP-specific: it applies to every secret every package materializes, including restic repository passwords, where the failure would not surface until a restore. | open |

| F57 | 2026-09-05 | Ingress / SSO | papercut | `ingress-tailnet` terminates with Caddy's internal CA, so every device that opens a page must install a root certificate by hand first.
